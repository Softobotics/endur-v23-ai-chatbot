 Section heading: Overview.
 Text content: The Automatic Notification Engine (ANE) is a notification engine used by the System to broadcast data changes to the OLF system’s client applications.  This is done so that all clients do not need to continuously “re-query” data from the database.  This is reflected on the AVS side of the Trading Manager Browser screen and/or within the Active side of blotter listing screens. There are various types of data supported by ANE such as Transaction and Curves.  Each type supported by ANE must have a unique identifier, such as “tran_num” or “index_id.”  The ANE queue stores only the unique identifier along with the type identifier.  No detailed information is stored within the ANE queue about the data that has been modified.  Information about how the data changed, when it changed, or who changed it is accessible only by using the data source directly.  (For example, the ab_tran table for transaction updates) Any API (used internally or exposed externally to AVS or Visual Basic) that modifies data supported by ANE will add an entry to the ANE queue upon successful completion of that modification.  This entry contains the type of data and the unique identifier.  This occurs whether or not ANE is actually running.  For example, when a Transaction is inserted/modified an entry is put into the ANE queue by the same client application (Trading Manager) that initiated the update. The ANE Engine continually polls this queue and broadcasts the type and unique_id of all changed data.  It is deleted from the ANE queue once an item is broadcast.  See ANE Message Types .
