 Section heading: Description of AVS Functions/Stored Procedures.
 Text content: Note: These stored procedures may be called directly by outside applications. int ANE_GetNextMessage(TABLE *table, int message_type) - calls the stored procedure “get_next_ane_log_msg” This function retrieves the next “unprocessed” unique identifier for a given message_type.  The table returned by this function would be empty if there were no entries in the log for this message_type.  The table returned contains message_type, ane_log_id (internally generated by ANE), messsage_id (this is the unique_indentifier) and row_creation.  (This is the time ANE broadcasts the data, not when the change occurred.) int ANE_ProcessNextMessage(int message_type) - calls the stored procedure “process_ane_log_msg” This function marks the next “unprocessed” message as “processed”.  This is used a sort of  “transaction control” on reading/processing ANE log entries.  This function should be called only if ANE_GetNextMessage() retrieved data AND the data was successfully transferred to another table and/or external system. pseudo-code example: table=TABLE_New(); retval = ANE_GetNextMessage(table, AU_TRANSACTION_INSERT); if (retval != 1) EXIT_Fail(); if (TABLE_GetNumRows(table)) /* If there is some data to process */ { tran_num = TABLE_GetIntN(table, “message_id”, 1); Retrieve some data from the database for tran_num Write the data to a file, send the data to another database, or write the data to a user_table if (the above process completed successfully) { ANE_ProcessNextMessage INSERT); }  int ANE_PruneMessageQueue(int message_type) - calls the stored procedure “prune_ane_log_que” Run this stored procedure periodically to “Prune” the log.  ANE_ProcessNextMessage “marks” the message as “processed” but does not delete data from the log. .
