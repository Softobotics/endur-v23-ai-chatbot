 Section heading: Layout of Import/Export File.
 Text content: The Import and Export functions can only import and export files that conform to the new (general) import/export format. The following information provides information on the file format. The source file defines objects that are to be imported and processed by the user program.  There can be multiple objects per file.  An object could be a Volatility (VOL), Correlation (COR), Deal, Profile, etc. Objects are represented in the import file by two types of records, header (HDR) records and data (REC) records.  All REC records must first be explicitly defined with a corresponding HDR record. · Header records (HDR) are the object definition.  They describe the fields that make up a REC and describe the columns in the table that will be built. · Data records (REC) contain the actual data and must match the preceding HDR definition for that object. The basic format of the file is as follows: HDR, OBJECT_TYPE, field_name1, field_name2, ... REC, OBJECT_TYPE, field_val1, field_val2, ... REC, OBJECT_TYPE, field_val1, field_val2, ... where,  HDR - Header record tag.  Identifies that this is a header record and describes its corresponding data records for the object represented by OBJECT_TYPE. REC - Data record tag.  This is the actual data corresponding to the OBJECT_TYPE . OBJECT_TYPE - The type of object being imported, e.g., IDX - indexes VOL - volatility COR - correlation DEAL - deal PROFILE - profile records SIMDEF – simulation definition SIMDEF_SCDEF – simulation scenario definition SIMDEF_SCRES – simulation results  field_nameX - Identifies the column name for the data that follows. field_valX - The actual data  Column 1 and column 2 are required fields.  All other columns are optional given that HDR records and REC records match for an OBJECT_TYPE. The HDR record applies for all the following REC records of the same OBJECT_TYPE until overridden by a new HDR record for the OBJECT_TYPE. If an OBJECT_TYPE is read from the file and the corresponding HDR record cannot be found for the OBJECT_TYPE, the record is discarded.  If any HDR line is not in correct format, i.e. containing all the names exactly as shown (with the exception of " field_name " that is optional), the import/import will return immediately and report an error.  There can be a mix of formats and objects as long as the preceding HDR records correctly describe the name and number of fields for the corresponding REC records for each OBJECT_TYPE.  Multiple object types may be contained in the same file.  At any time in the file, the object type may switch.  The format of the data records must match the previously read HDR record for that OBJECT_TYPE.  Note: Comments in the data file are preceded by the # character in the first position of a line. Blank spaces are significant.  They are not discarded. Blank lines are ignored.  The following is some sample data files:  #This is a comment.  #define import format and data record HDR,IDX,index_name,gpt_name,bid,offer,bid_offer,field_name REC,IDX,LIBOR.USD,O/N,5.4,4.3,,input REC,IDX,LIBOR.USD,1imm,,,5.4,close  #change the column definitions HDR,IDX,index_name,gpt_name,bid_offer,field_name REC,IDX,LIBOR.USD,O/N,5.4,spread  #multiple data objects in the same file #define records for both vol and index import HDR,IDX, index_name,gpt_name, bid_offer, field_name HDR,VOL,vol_name,shadow_name,dim_id,label1,label3,value_type,val1,val2 REC,IDX,LIBOR.USD,O/N,5.4,spread REC,IDX,CP.USD,S/N,4.3,input REC,VOL,VOL2005.LIBOR.USD,Official,2,2m,2.000,BO,14.0,15.0  #column order does not matter HDR,IDX,index_name,gpt_name,bid_offer,field_name REC,IDX,LIBOR.USD,O/N,5.4,spread #change column order HDR,IDX,field_name,gpt_name,bid  REC,IDX,input,CP.USD, S/N,4.3 # The previous blank line will be ignored .
