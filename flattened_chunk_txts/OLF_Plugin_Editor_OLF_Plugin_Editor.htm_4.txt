| Type | Description |
| Param | AParameterscript is used to prepare information to be passed to a main script. The tableargtis used to hold data to be passed to a main script. Parameter scripts can, but are not normally, run without a main script in a Task. |
| Main | AMainscript is the main script that contains the bulk of the reporting or process-specific code. A main script may be designated to run alone in a Task. |
| Page Viewer | APage Viewerscript is used to set the subscriptions and activate the Page Viewer. This kind of script may run alone in a Task. |
| Output | AnOutput Scriptis a script that runs locally in the Trading Manager after the main script has run.Warning: Output Scripts cannot be run alone in a Task. They require a Main script in the Task as well. |
| Include | This means the script can be used as an include script. This is so functions in one script can be shared.This required a license key (AVS_POUND_INCLUDE) in builds before August 27, 2003. It now is not controlled by licensing. |

| Log Script | V10.0r2 and later.If there is a check in this box, then the system will log the script.Script and task logging is enabled at the script level. Script logging can be enabled on a script by selecting theLog Scriptcheckbox. Task logging is automatically enabled if the main script of the task is configured for script logging. Both task and script logging are automatically enabled when a task/script job is run in a workflow in the Services Manager, or when running a Credit, Risk, or RTPE batch task.The following information is captured and stored when a task and a script are logged:Task information including task submitter and time submitted, module initiating the task and run site, the context in which the task was run (e.g., workflow definition, Credit/Risk/RTPE batch, and task status)Script Information including start and end times, memory use before and after execution, script submitter, and executing moduleErrors generated during the script execution and logged in the error logReferences to reports generated during the script executionScript-generated Posted Statuses are logged with the script. Status information can be logged with the function SCRIPT_PostStatus()Script-generated Return Data is logged with script. EXIT_Succeed() and EXIT_Fail() functions now take an optional return table argument. The return table is logged if script logging is enabled.This information is saved in the database. This is not stored in a file. This information takes up a log of space, so clients should purge this data keeping just a few months worth in the production database (depending on the volume of data for the client).SeePurging Data. |
