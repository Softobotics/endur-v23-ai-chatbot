# Query Manager

## Overview

The Query Manager 
	 is used to search and extract information from the system. A query 
	 is performed to retrieve information from the database based on the 
	 query criteria specified by the user. Any criteria entered into the 
	 Query window limits what is retrieved from the database. For example, 
	 in the Trading Explorer Desktop, if a Bond toolset is 
	 specified in the ToolSet field of the Transaction table, 
	 the system will only display bond deals in the Trading Explorer 
	 Desktop.

The parameters for 
	 filtering data differ and depend on the functionality, desktop, or 
	 system manager driving the query. The search criteria defined may 
	 be very broad to retrieve many items or very specific as to retrieve 
	 just one item.

## Accessing the Trades Query Window

Note:   There 
	 are multiple ways to access this window; however, only one way is 
	 defined because some features can only be accessed via this procedure.

1.    Start 
	 the Trading Explorer.

2.    Click 
	 the  icon, or select Trading 
	 Explorer à 
	 Query Manager. The following window displays:

### Logical Operators

It is very important 
	 that users understand the logical operators AND, OR, 
	 and NOT. When a query is executed, the criteria entered for 
	 different fields (such as ToolSet and Tran Status) 
	 takes an AND relationship, while the different criteria entered 
	 for a specific field takes an OR relationship. For example, 
	 if the user enters FX and Cash in the ToolSet 
	 field, and New and Validated in the Tran Status 
	 fields, then any transactions in the database that have a toolset 
	 value of FX OR Cash, AND a Tran Status of New 
	 OR Validated will be retrieved. To reiterate,

·         the 
	 different rows on the query screen are ”ANDed” together

·         the 
	 comma-separated values are “ORed” together

To perform more 
	 complex queries, users may use additional logical operators such as

·         less

### Character String Fields

Multiple items of character reference strings, 
	 such as Reference and Ticker, must be separated with 
	 commas. The multi-line editor may also be used to aid in entering 
	 multiple values.

Wildcard characters such as the asterisk (*) can 
	 be embedded within the string to search string fields such as “Reference”. 
	 You could enter *JPY*97 to get anything that has both “JPY” and “97” 
	 embedded within the string.

Note: When querying for a value that is 
	 a floating point number, the system uses an epsilon value to search 
	 for a number that is within an acceptable range rather than looking 
	 for an exact matching value. If the end-user wishes to find an exact 
	 match, then they must put an equal sign before the value (for example:, 
	 =4.079).

## Frequently Asked Questions

**Question: The query is returning more trades 
	 than I expected. For example, I only queried for trades with a status 
	 of "Validated", but I am also getting trades with a status 
	 of "New". Why is that?**

Answer:

The system auto-adds 
	 all deals included in a Composer. So if you have a composer 
	 with a status of Validated and it contains 10 deals with a status 
	 of new, you will see that the system will retrieve those additional 
	 trades as well. This can cause a problem with EOD (End-of-Day) Saved 
	 Queries used for EOD simulations. EOD simulations are run for one 
	 portfolio at a time. If you have a query that returns deals in more 
	 than one portfolio, the EOD will return an error message. If you have 
	 a Composer that contains deals in several portfolios, then those deals 
	 will be brought into the query, which can cause problems. The solution 
	 is to exclude Composer deals from your query.

**Question: The query is not returning deals that 
	 I am expecting it to return. Why is that?**

Answer:

The Query Manager 
	 has some security restrictions based on what portfolios for which 
	 a user has authorization. For example, you could have portfolios 1 
	 through 10, with 100 trades in each. If a user only has authorization 
	 for two portfolios, only the 200 deals in those two portfolios will 
	 be retrieved.

**Question: How can I retrieve deals with a status 
	 of "Matured", "Pending" or "Template?"**

Answer:

The Trading Query 
	 (such as the Query Manager for the Trading Manager) defaults 
	 to look for deals with a status of New and "Validated". 
	 To view deals from any other status, simply set the “Tran Type” field 
	 to the appropriate status, for example, Matured, Pending, 
	 or Template.

Q: How can I 
	 retrieve Master Instruments/Holding Records?

Answer:

Set the Tran 
	 Type field to Holding.
