Plugin Editor

Overview

The Plugin Editor is used to edit and view plug-ins. The Plugin Editor is available in V9.0r1 and up.

Accessing This Window/Screen

This window can be accessed via multiple paths in the system. Listed below are two options.

From the Admin Manager:

1.    From OpenLink Central start the Admin Manager.

2.    Select the System Administration tab.

3.    Select the Plugin Editor icon.

or

From the System Monitor:

1.    From OpenLink Central start the System Monitor.

2.    Select the Plugin Editor icon.

Fields

This window contains the following fields:

Field

Description

Name

The name of the Script.

Project

Name of the project to which the plug-in is associated.

Type

Indicates the type of script. There are five different types:

Type

Description
Param

A Parameter script is used to prepare information to be passed to a main script. The table argt is used to hold data to be passed to a main script. Parameter scripts can, but are not normally, run without a main script in a Task.

Main

A Main script is the main script that contains the bulk of the reporting or process-specific code. A main script may be designated to run alone in a Task.

Page Viewer

A Page Viewer script is used to set the subscriptions and activate the Page Viewer. This kind of script may run alone in a Task.

Output

An Output Script is a script that runs locally in the Trading Manager after the main script has run.

Warning: Output Scripts cannot be run alone in a Task. They require a Main script in the Task as well.

Include

This means the script can be used as an include script. This is so functions in one script can be shared.

This required a license key (AVS_POUND_INCLUDE) in builds before August 27, 2003. It now is not controlled by licensing.

Category

The Script Category. When creating new scripts, if you want the script to appear in specific categories, be sure to select one or multiple categories in the script category field in the script editor.

A script can have multiple categories and appear in more than one category list, although there will be only one copy of the script.

See Script Category.

Path to Plugin

Lists the location where this plug-in is saved.

Owner

The user ID who is the owner of the script.

Group

The name of the security group to which the script is assigned. This is a read-only field. To set this up, you must go the properties window.

See Properties.

Log Script

V10.0r2 and later.

If there is a check in this box, then the system will log the script.

Script and task logging is enabled at the script level. Script logging can be enabled on a script by selecting the Log Script checkbox. Task logging is automatically enabled if the main script of the task is configured for script logging. Both task and script logging are automatically enabled when a task/script job is run in a workflow in the Services Manager, or when running a Credit, Risk, or RTPE batch task.

The following information is captured and stored when a task and a script are logged:

  • Task information including task submitter and time submitted, module initiating the task and run site, the context in which the task was run (e.g., workflow definition, Credit/Risk/RTPE batch, and task status)
  • Script Information including start and end times, memory use before and after execution, script submitter, and executing module
  • Errors generated during the script execution and logged in the error log
  • References to reports generated during the script execution
  • Script-generated Posted Statuses are logged with the script. Status information can be logged with the function SCRIPT_PostStatus()
  • Script-generated Return Data is logged with script. EXIT_Succeed() and EXIT_Fail() functions now take an optional return table argument. The return table is logged if script logging is enabled.

This information is saved in the database. This is not stored in a file. This information takes up a log of space, so clients should purge this data keeping just a few months worth in the production database (depending on the volume of data for the client).

See Purging Data.
