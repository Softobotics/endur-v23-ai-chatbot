Task Statuses

The following statuses will occur when running Tasks.  These statuses are contained in the table “job_status:”

#

Status

Description

0

Initializing

This status indicates that the task has begun running.

1

Waiting

This status indicates that the task is waiting to run. 

2

Ready

This status that the task is ready to run.

3

Blocked

This status indicates that the user who tried to run a task does not have the proper security privileges.

4

Submitting

Indicates that a script is being loaded into the Script Engine.

5

Running

Indicates that a task is running.

6

Param Compile Error

Indicates that there is a problem related to a Parameter Script in a task.

This status means that the script is not compiling correctly and cannot be run.  There may be a line or lines within the script that are incorrect.

7

Display Compile Error

Indicates that there is a problem related to a Display Script in a task.

This status means that the script is not compiling correctly and cannot be run.  There may be a line or lines within the script that are incorrect.

8

Main Compile Error

Indicates that there is a problem related to the Main Script of a task.

This status means that the script is not compiling correctly and cannot be run.  There may be a line or lines within the script that are incorrect.

9

Succeeded

This status indicates that the task has been run to completion and the business logic within the report was met.

10

Failed

This status indicates that he task has been run to completion, but the business logic was not met within the report. 

Check for messages on the console stating what logic was not met. 

Not all scripts check business logic and therefore some scripts will never end with a status of Failed.  Check a Script's header to see what business logic may cause it to fail, if any.

Technical Note:  The EXIT_Fail() script function causes scripts to immediately exit with a status of failed.

11

Aborted

The aborted status means someone manually stopped the task when it was running.

12

Orphaned

This status may occur when a task is being run and it contains links to a script that has been incorrectly labeled or is not present in the system.

13

Crashed – Retrying

This status indicates that the task has crashed but is being reloaded into the Script Engine to be run again

14

Engine Crashed

This status means that the task started running, but was not able to run to completion.  Possible causes include a bug in the script or not enough available memory on the machine running the script.

15

Transmission Failure

Indicates that the Task was set to run a machine that is not on or running the system.

You specify the system on which you want to run the Task in the Task Editor window in the Run Site field.  If that system is down, the Task will try to run on the system specified by the Alternate Site field.  If the Alternate Site is not running, the Task returns a status of Transmission Failure.

If you want to ensure the Task runs when you run it, try setting the Run Site to Local and run the Task just to make sure it is working.  Setting the run site to Local means that when the Task runs, it runs on your machine. 

An example of how a Task runs is the Missing Settlements Instructions report.  If it runs to completion and there are no missing settlement instructions, then it will end with a status of “Succeeded.”   If there are missing resets, it will end with a status of “Failed.” 

This feature is useful because if you run the script from the Trading Manager you can see the script's exit status.  If this script ends with a status of “Succeeded,” you don't need to check the report.  If you were to check the report you would see that it would read something similar to, "no missing settlement instructions".  If the script ends with a status of “Failed,” you should check the generated report to see which trades are missing settlement instructions.
