Backwards Compatibility

Overview

This is a list of items that are included in the system for backwards compatibility.   New clients should avoid using these features.   They are not supported for new clients (there is no testing/documentation). 

 

Also included is a list of features in the system that were partly implemented in the system.  These should not be used by clients.  Depending on various factors, these items will either be fully implemented (in which case they may be used) or removed entirely from the system.

21

The ticker file functionality (files ending in .tic) is not supported for new clients.  This functionality is in the system for backwards compatibility.  Here is the history:  This functionality was added a very long time ago.  At the time it was added, it worked with most deal types (Toolset/Instrument Types) in the system.  However, as new Instrument Types, and Toolsets were added, the functionality to produce ticker files was not updated.   Ticker files will get generated for most, if not all, toolsets, because it is generic code, but the files won’t make business sense in all cases, especially for the newer Toolsets/Instrument Types.  This functionality has been replaced with the ability to run a Operation Services Post-processing script to write out a file with deal details. 

22

Setting environment variables that can be set in the System Wide Configuration module in a runscript is supported only for backwards compatibility.  

The settings that can be set in the System Wide Configuration screen are saved in the database.  They can also be set in the runscript (batch file used to start the system).  If they are set in the runscript, then they override whatever is set here.  It is recommended that settings are set in this screen over the runscript, which is just supported for backwards compatibility.

Some Environment Variables can only be set in the runscript.  These are sometimes called “External System Wide Configuration” values.  These are settings such as directory locations that would not be useful if saved in the database, because when the database is loaded in a different location, the directories may not exist.

See System Wide Configuration

29

Authorization Records (rows in table ab_tran with a  tran_type = 1) should not be used by clients. 

Authorization Records are in the system for Backwards compatibility.  They continue to be generated in Version 8.0, but users can disable them.  The default for version 8.1 and up for the system is to not generate Authorization Records.  Clients can generated Authorization Records even in V8.1 and up if needed.  OpenLink recommends that clients do not generate Authorization Records. The system wide configuration variable is AB_SAVE_AUTH_RECORD_INTO_AB_TRAN.

See Environment Variables
