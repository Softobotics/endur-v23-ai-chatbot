Task Properties

Overview

Each Task has permissions associated with it.  The person who creates a script is the owner.  The owner can associate Read, Write, and Execute Permissions to the script for himself, to a security group, and to the public.

Note: This page is for v90r1 and later. For v82r1 and earlier, see AVS Task Properties.

Accessing This Window/Screen

This window can be accessed by following the steps below.

1.    Start the Trading Manager.

2.    Select Script à Task Editor.  The Task Editor window displays.

3.    Select File àOpen.  A pop up list of available tasks in the database displays.

4.    Select File à Properties.

The following window displays:

Note:  The settings in this window are the System-upgrade defaults for existing Tasks.  The Owner and Group information and Owner/Group/Public permissions can be modified. However, it is also important to note that only one security group can be assigned to each task (when one group is assigned the privilege, any previously assigned group will lose the privilege).

Fields

This window contains the following fields:

Field

Description
Name

This is a variable character field of up to 32 characters.  It represents the name of the Task to which privileges are being applied.  If the Task is new and no name assigned yet, data can be entered.  Otherwise, this is a read-only field. 

Directory/Full Path

Together, these two fields indicate the path and directory in which the task is located.  During a System upgrade, all of the existing tasks in the database are placed in the /Task/Site directory.  New tasks are saved to the /Task/Site directory with your user ID as the owner.  Left-click in the Directory field to change the directory of a new task.  A pick list displays from which to chose a new directory.

Version

This indicates the number of the current version of the task permission.  The version number is increased each time permission is changed and saved.

Owner

This is a pick list field of available user IDs.  The pick list is disabled if this is a new task.  Otherwise, select a user as the owner.  The user ID of the person who creates the task is initially indicated as the owner.  Only someone with the associated permissions, such as the Owner or someone (preferably the database administrator) with the security privilege of either:

  • Directory Node System SuperUser Group
  • Directory System Task SuperUser Group

Note:  If the original owner of the task is changed, the original owner may lose access rights to the task if they are not part of the group to which the task is assigned.

Security Group

This is a pick list field of Security Groups (Security Groups are set up in the Admin Manager).  Choose the group whose members have rights to the selected task and its associated permissions.  A security group Task DIRNODE Developers was created and assigned as a default to each of the existing tasks after a database upgrade.

Note:  The default name of this Security Group (Task DIRNODE Developers) can be changed in the Admin Manager. 

The default group task assignments can be changed.  Only someone with the associated permissions, such as the Owner or someone (preferably the database administrator) with the security privilege of either:

  • Directory Node System SuperUser Group
  • Directory System Task SuperUser Group

Owner/Group/Public Permissions

These are check box fields that can be toggled on and off.  They grant read, write, and execute privileges to the owner of the task, the security group assigned, and to the general population of users.

Note:  Execute Permissions are checked by the script engine.

Assigning Access Rights for a Task to Security Groups

The owner of a task has the rights to assign the rights to access this task to one security group in the system.  For example, a task that is relevant to the job functions of back office personnel can be restricted to that group. Each time the Task is assigned to a group and saved, the previous definition is overwritten.

Access rights can be assigned by performing the following steps:

  1. Open the AVS window.
  2. Select a task.
  3. Select Script à Task Editor. 
  4. The Task Editor window displays.
  5. Select File à Properties.
  6. The Task Properties window displays.
  7. Right-click on the “Groups” field.
  8. A pick list of all groups to which the user has access will display.
  9. Scroll down to the group to be selected.
  10. Click the Save button.
  11. The user will be prompted to confirm the changes before the System saves them.

IMPORTANT:  If no group is assigned to a Task, it means that ALL users can run it.

Having the Proper Rights to Assign Security Group Access

The owner of the task has the right to assign access to a task to specific security groups.  However, the task’s owner must also have rights to those groups. 

For example, a task owner must have access to the Front Office group to give it rights to run a task.  Otherwise, the owner will not see name of the group in the pick list from which the group is selected.

If the task owner has Administrator privileges and encounters this problem, it problem can be solved as follows:

  1. Navigate to Reference Explorer Personnel (V10.0r2 and later) or Reference Personnel Listing (V10.2.1 and earlier).
  2. Double click on your user name.
  3. The Personnel Editor window displays.
  4. Query for the Group’s owner
  5. Click the Security Groups radio button.
  6. In the “Available Groups” field, select the security group to be added.
  7. Click on the group name and click the Add button.
  8. Select File à Save.
  9. Go back to the Main Menu and click the Refresh button.
  10. Close and re-enter the Task Editor.
  11. The added security group(s) should appear in the picklist from which they are selected.
