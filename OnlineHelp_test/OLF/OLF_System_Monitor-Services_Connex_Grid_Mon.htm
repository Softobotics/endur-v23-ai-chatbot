System Monitor - Services - Connex Grid Monitor

Overview

The System Monitor – Services tabs work with the Services Manager module. Many of the components viewed in this tab have been previously configured in the Services Manager.

The Connex Grid Monitor shows details of processes, functionality and information related to OpenLink’s Connex integration framework. It provides management facilities around Connex grid configuration and shows running integration gateways that may or may not take advantage of the underlying Connex grid. The monitor shows configured Connex engines (grid engines) and standard/custom gateways as well as provides management facilities on jobs, messaging, engines and exceptions.

This tab is only available in V8.0r1 and up.

Access to this window is controlled by Security Privilege #29255, Access Connex Grid Monitor Tab.

Views

There are two views available on this tab controlled by radio buttons. The Grid Monitor button provides the same view described in the Services Manager and additionally provides the QA Test Results panel, a simple application that tests the gateway cluster. The Running Services view and the QA Test Results panel of the Monitor view are detailed on this page.

Running Services View

The default view of the monitor shows all Connex gateways and services that may or may not take advantage of the Connex grid. Connex grids are configured in the Services Manager module. This view contains the following fields:

Field

Description

< Gateway/ ConnexGrid XML Engine >

Displays Connex gateways and grid engines, grouped by cluster, in tree view form. Click the field or the +/- icons to expand/collapse the components in the group.

Status

Displays the status of the Connex gateways and grid engines. Statuses are color-coded.

See Gateway Status

Server Node

Displays the name of the server node hosting the selected engine or service.

Submitter

Name of the user initiating the Connex gateway.

Message User

V81r1 and later.

Only applies if the job is a “Message.” The user who accepted the message.

Last Start

The date and time the Connex gateway last started running.

Last End

The date and time the Connex service stopped running.

Max Run Time

V81r1 and later.

The time allotted for a job to run. If a job does not complete in the allotted maximum run time, the job logs as “FAILED. The format used is hours.minutes.  For example, “5” would be five hours, “4.32” would be four hours 32 minutes, and “0.2” would be 2 minutes.  Minutes must be less than 60. Therefore, entering a time 3.67 is not allowed.

Exception Job

V81r1 and later.

The exception job that will execute in case the XML engine instance fails. This feature is useful to administrators who need to be notified upon system failure.

This is defined in the Connex Grid Cluster Definition window.

What Next

Instructs the system what to do if the grid/XML engine fails. The available options are:

Value

Description

Continue

If the grid/XML engine fails, the workflow will just continue.

Rerun

If the grid/XML engine fails, the workflow will keep running the job until it succeeds or the “Max. Run Time” is exceeded.

Stop

The grid/XML engine will stop processing once it completes or fails.

Subscription

V81r1 and later.

The text string that will launch a workflow in response to a message containing the text string.

Kill Time

V81r1 and later.

The amount of time [secs] that must elapse without receiving a request before a reserve engine is removed (stopped).

Rerun Num

V81r1 and later.

A count of allowable reruns.
